Emissions diagnostics over generic OBD-II -- readiness monitors and Mode 06 test results -- plus honest graph axes and log sharing straight from the phone.

## What's new

This is the first release cut from `main`. It gathers the work that shipped as the
`fuel-calibration` and `history` prereleases, and adds emissions diagnostics on top.

### Emissions diagnostics
- **"check readiness"** reads the I/M readiness monitors over generic OBD-II and prints a
  California verdict. It cannot be done over SSM, so this is a second protocol stack on the
  same K-line pin: KWP2000 fast init with an ISO 9141-2 5-baud fallback, serviced inside the
  polling loop like a DTC read. Gauges stall for the second or two it takes.
- **"debug"** captures every probe verbatim as `obd_dump_<timestamp>.json` -- request frame,
  raw response, payload -- and interprets nothing. The bytes we cannot yet read are exactly
  the ones being hunted.
- **"sweep"** asks all 256 Mode $06 and 32 Mode $05 test IDs one at a time, about a minute
  with the gauges stalled. Two rounds of guessing at an unpublished TID map had already
  failed; measuring was cheaper than a third guess.
- **Mode $06 now decodes on this ECU.** The sweep found five live TIDs -- $41, $81, $83,
  $84, $85 -- and the support bitmask corroborates each one. The FSM's numbering is simply
  wrong for this car. Records are five bytes: CID, 16-bit value, 16-bit limit.
- The finding the exercise was for, from TID $83: the 0.020-inch EVAP leak diagnosis reads
  0 against 0xFFFF while both its siblings carry real results. That test has never produced
  a result on this car, which matches the fuel tank pressure logs.
- Scaling and limit direction are still unknown and are not guessed at. Value, limit and
  their ratio are meaningful without units.
- **Mode $09** rides along: VIN, Cal ID and CVN are now recorded from the stock ROM. Those
  are the values a Smog Check compares, so this is the baseline to restore to if a tune ever
  needs backing out.
- **The KWP2000 session is now closed properly.** On the first run at the car, readiness
  worked and then SSM never came back: a session opened and abandoned leaves the ECU
  ignoring SSM until the key is cycled. `disconnect()` now sends StopCommunication, SSM
  restoration retries three times, and the protocol swap delay went from 200 ms to 500 ms.

### Graphs
- Y ranges we can defend are fixed; everything else autoscales with 10% headroom instead of
  being pinned to 0..100. Knock correction no longer sits on the bottom edge with real
  events drawn below the plot.
- Fuel Tank Pressure was listed 60x too wide -- +-2 bar for a sensor whose whole physical
  range is +-3.2 kPa -- which drew the EVAP signal as a flat line. Manifold relative
  pressure, ignition timing and atmospheric pressure were wrong in the same way.
- Autoscale snaps to 1/2/5 x 10^n, grows the instant data escapes, and shrinks only after a
  smaller axis has been available for three seconds. Data that never goes negative gets a
  zero floor.
- Tap a graph to maximize it across its row rather than one at a time across the grid, and a
  maximized graph shows the parameter's full name.

### Logs off the head unit
- **"share logs"** lists what is on disk, zips it, and opens the system share sheet.
  **"clear logs"** deletes it and reports the space freed. No cable, no adb.
- The active debug log is truncated rather than deleted, so logging survives a clear, and
  the CSV writer reopens if its file goes away mid-drive.

### Correctness
- A parameter that fails to parse no longer shifts every later value in the same SSM row.
  The response is positional, so one failure used to produce plausible in-range wrong
  numbers in the graphs and the CSV with nothing marking them suspect.
- Fixed a unit test that read its own from/to arguments backwards.

### Build
- `release.sh` archives a named APK copy in `apks/` after the version and checksum checks
  pass, so there is a record of which build is on the head unit.

### Artifact
- `app-debug.apk` is a debug-signed build.
