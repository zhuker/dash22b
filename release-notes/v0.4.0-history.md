Graphs now hold ~20 minutes of history, with tap-to-maximize and All/1min/5min windows.

## What's new

### Graph history
- Replace the 50-sample `EngineDataHistory` list with a columnar `HistoryStore`: one
  `FloatArray` per parameter plus a shared timestamp array in a fixed ring.
- 48 bytes per sample for ten parameters instead of ~600, so the default 12,000-sample
  capacity holds about twenty minutes in ~576 KB.
- Graphs draw the last five minutes by default, up from roughly five seconds.
- Queries return min/max/mean per bucket, bucketed to the graph's pixel width, so render
  cost no longer grows with history depth and a boost or knock spike stays visible when
  zoomed out.
- Gaps -- an ECU dropout, or a parameter leaving the preset -- break the line instead of
  holding the last value.
- Values are stored in their SSM source unit and converted at draw time, so changing a
  gauge's display unit reconverts the whole retained series with no seam.

### Graph controls
- Tap a graph to expand it across its row; tap again to restore.
- All / 1 min / 5 min buttons select how much history every graph shows. "All" spans
  everything the store still holds, which is bounded by the ring, not by the drive.

### Build identity
- `versionName` and `versionCode` come from `git describe` instead of a hardcoded "1.0",
  so the APK, the manifest and the release tag finally agree.
- The Messages tab welcome banner shows the running version plus a one-sentence summary,
  readable on the phone with no cable attached.
- Builds made off-tag or with local edits are marked `dev` and `-dirty`, so a work in
  progress cannot be mistaken for a release.
- Library `BuildConfig` is enabled from the root build, leaving the pinned
  usb-serial-for-android submodule pristine.

### Artifact
- `app-debug.apk` is a debug-signed build.
