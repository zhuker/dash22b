GPS joins the dash -- speed, track logging, a real trip meter and odometer -- and gauges refresh about 3.5x faster with SSM fast poll.

## What's new

### Gauges about 3.5x faster: SSM fast poll
- **Gauge reads now use SSM continuous-read mode.** The address list is sent once and the
  ECU streams responses until the line is broken, so each sample pays only for the return
  leg. At 4800 baud the request was the expensive half. For the 13-parameter gauge set this
  car went from 6.3 Hz to 21.8 Hz in the Python port's measurements, and the gain grows
  with the parameter count.
- **Every streamed frame is validated**: length, tester and module id, response type,
  checksum. A bad frame breaks the stream and replays the previous sample once, but only if
  that sample came from the same parameter list. A frame decoded against another layout
  gives plausible numbers in the wrong gauges.
- **The stream is broken before anything else talks on the K-line**: a preset change, a DTC
  read, an ECU reset, and every OBD-II takeover (readiness, debug, sweep). A streaming ECU
  would otherwise keep clocking frames onto the wire underneath them.
- **The poll loop no longer sleeps between fast reads.** The ECU sends whether or not we
  read, so a fixed delay made the data stale and then overflowed the cable's FIFO.
- After three failed fast reads in a row it falls back to single reads until the next
  reconnect, rather than stalling the gauges.
- **A `Poll:` line in the debug log once a minute** shows the mode, the Hz achieved, stream
  restarts, bad frames and replays, so a drive can be judged from the log file alone.
- Graph history grows from 12k to 36k samples, about 27 minutes at the new rate. 12k would
  have covered about 9. Graph redraws follow the sample rate and are not throttled yet.

### GPS
- **Speed and position are logged with or without the ECU**, one row per fix, to their own
  `gps_<timestamp>.csv`. Position is kept as a Double end to end; a Float latitude is
  coarser than the receiver.
- **GPS Speed is a parameter.** Put it on a gauge, or graph it against Vehicle Speed to see
  speedometer error.
- **The trip and odometer readouts are real.** They used to be the constant strings
  "000006 km" and "005.6 km". Distance only counts with evidence of motion, and inaccurate
  fixes, long gaps and teleports are rejected, so a parked receiver drifting over a lunch
  stop doesn't invent kilometres. The odometer persists across runs.
- **The clock prefers satellite time**, which is right even on a head unit whose own clock
  has never been set.

### Fixes
- **Crash on launch** when registering the GNSS status callback from a worker thread with
  no Looper.
- **Location permission is requested on every API level**, not only on Android 12+. Before
  this, older head units never asked, and the TPMS scan quietly returned nothing.
- **The foreground service starts once the app is actually in the foreground.** Before
  Android 12, starting it earlier silently denied it location access for its whole life.
- **The TPMS scan keeps itself alive.** A failed scan retries with backoff instead of
  sitting dead for its whole cycle, turning Bluetooth back on wakes it immediately, and it
  no longer pauses mid-drive with the app in the background.
- `.gitignore` no longer swallows new source files under `app/src/main/java/com/example/`.
